## b15 (2026-10-19)

Rollover verification by the new session's first request, reply-shape failures of the `[compaction]` turn told apart
from engine failures, and turn timeouts told apart from account faults (`loops/b15.md`, founder go 2026-10-18;

## What changed
- Verification (requirement 1): `verify_compaction()` without an argument reads the new id's transcript
  (`find_claude_transcript` under the engine's config dir) and takes its first `assistant` record's context
  (`_transcript_first_context`, the b11 scan's tolerance: a missing file, an unreadable file or an unparsable line
  contributes nothing); the record carries `source: "transcript"`. A transcript with no assistant record yet keeps the
  verification pending. When no transcript file of the new id exists at all, the turn path's `turn_tokens` settles it
  as before (`source: "turn"`; amendment 1: the baseline b11 fakes write no transcript). An explicit argument keeps
  the baseline meaning (`source: "argument"`). It runs at every Claude turn's end and at the start of
  `compaction_due`, before the guards. A measurement from before the last rollover never makes a compaction due
  (`_measurement_since_rollover`: the last measured turn must come after the last `kind: compaction` row); without
  it, the settled verification let the old session's 305,024 trigger a second rollover at the same tick.
- `hydra status`: the compaction line gains `| session start: <S> tokens` right after the context number when the
  current session's transcript has its first assistant record (absent otherwise; amendment 1, so the b11 status
  pins stay byte-identical).
- Shape failures (requirement 2): `COMPACTION_MESSAGE` states the whole contract (MEMORY.md, MANAGER-HANDOFF.md,
  `compacted` followed by the `---HANDOFF---` block and its five line names). A `[compaction]` reply with no valid
  handoff or with MEMORY.md unchanged keeps the old id with the baseline error texts; the first miss of a streak
  records `shape_failures: 1` (state and ledger record), leaves `failed_at` alone, keeps `COMPACT` and the schedule,
  posts nothing, and the next turn boundary runs the compaction again with the message followed by the sentence
  naming the miss (`COMPACTION_MISS_SENTENCES`). The second consecutive miss backs off as today; a rollover resets the
  streak (`_finish_rollover_bookkeeping`); an rc != 0 backs off at once as today.
- Turn timeouts (requirement 3): the vendor boundary counts the session transcript's `assistant` records before the
  call and after an rc 124 (`_assistant_records`, `_note_timeout`, on the per-turn `_run` and the persistent `send`);
  the attempt row carries `timeout: "working"|"silent"` and `transcript_records: k`. A working timeout (k >= 1) is
  classified `timeout`, raises an uncertain `EngineFault` that never asks the b14 valve, opens no episode and moves
  nothing; `turn()` writes the turn row with `timeout`, `transcript_records` and `timeout_at` first, answers the
  CLI/self events as unavailable with the same text, then queues the one line `manager turn timeout: turn <n> on
  <acc> (<model>) ran <T> s while working (<k> replies); its events were answered as unavailable` (id
  `timeout-<n>`); `_reconcile_timeout_notice` queues a durable row's missing line at start, once. A silent timeout
  (k = 0) is a fault exactly as today, with today's row (classification `other`) and fault text `timeout`
  (amendment 1: the frozen b12 and b14 contracts pin both); its turn row says `timeout: "silent"`.
- `hydra status` prints `last turn timeout: <PDT> turn <n> working (<k> replies)` or `... silent` right after the
  compaction line for a timeout within the last 24 hours (`_timeout_status_line`; `status_text`'s "now" follows a
  Supervisor's controlled clock when one is registered for the home, the wall clock in production).
- `Supervisor.persistent_status()` (the module-level view of this home) exists as the README named it.
- README: the compaction policy (verification by the transcript, the `[compaction]` message, shape failures, the
  `session start:` and `last turn timeout:` lines) and rule 4 (silent vs working timeouts).
