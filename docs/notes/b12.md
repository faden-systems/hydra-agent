# b12 notes — the manager's model floor

## What changed

The ladder. `manager/supervisor.py` now defines `MANAGER_LADDER` (tier 1 `claude-fable-5-1` on claude-r2d2 then
claude-l, tier 2 `gpt-6-astra` on codex, tier 3 `claude-opus-5-5` on claude-r2d2 then claude-l; the last tier is the
floor) with `manager_ladder`, `ladder_steps`, `floor_model`, `ladder_position`, `enforce_engine_policy` and
`Supervisor.engine_ladder`. A `config.json` `engine_policy.ladder` override can narrow or reorder the ladder but
never extend the founder-approved set; when the override is invalid in any way (an unknown account, the wrong family,
a model outside the set after alias resolution, a repeated pair, an empty list or a non-list) the whole override is
ignored, the default ladder applies, and one log line per process names the first problem. `run_engines` walks the
ladder steps. It starts at the configured primary's own step, then tries the other accounts in that tier, then the
lower tiers, then wraps to the tiers above. During an active fallback episode it starts at the configured pair's tier,
and within that tier the persisted engine file's step goes first, which keeps the baseline "the exhausted account is
not retried first" behaviour. Each step runs exactly that step's model. The same-account model retry is gone:
`engine_fallback.claude_models` is ignored and logged once. A stale engine file outside the ladder is never invoked.

The refusal. `hydra engine` and `@manager engine` parse the command as before, then call `enforce_engine_policy`
before `set_engine`. A refused pair, or a mode-only change on a stale pair, gets one line: `model <id> is not on the
manager's allowlist (floor ...); allowed: ...; nothing changed (engine: ...)`. On the console it exits 2; in Slack
it is a reply. Neither the engine file nor `engine-runtime.json` changes. `hydra attach` exits 2 without starting a
process when the engine file's pair is outside the ladder. Both surfaces resolve aliases from the home's models.json.

The unavailable line. When every allowed step fails, the turn keeps its existing bookkeeping (the error record,
`logs/retry-after`, the failed reaction, events left pending). Slack events no longer get a per-thread note. Instead
there is one top-level dev-channel line per unavailability episode, `manager unavailable: all allowed engines failed
(<reasons>)`, with one `tier <k> <acc> (<model>): <what>` entry per step in the order tried. The reasons text is cut
to 1,000 code points and the error text to 80. `logs/unavailable.json` is written before the line is queued
(notice id `unavailable-<episode_id>`), with a `queued` flag; restart and close both reconcile the flag, so the line
is never lost or duplicated across a crash. The next served turn sets the episode id to null. CLI reply files and
self-event routing keep their existing behaviour with the new wording.

The status line. `status_text` adds `engine policy: floor ...; active tier k/n acc (model); ladder ...` right after
the `engine:` line. It covers a stale pair, an ignored-policy suffix, field caps (40/60/80) and a 400 code-point
bound. Fallback notices now name the tiers (`tier k/n acc (model)`).

The founder rules of 2026-10-15 (loops/b12.md requirements 10 to 14; candidate 39b493a squashed onto main and
finished by the manager, no coder). One: inside the configured tier the account that last worked serves first and a
usage failure on it (`credits`, `usage_limit`, `auth`) moves to the other account of that tier before any lower tier;
Astra is reached only when both Fable accounts are out, the floor only when Astra is out. Two: a success on a higher
tier moves the manager back up at once; the configured pair closes the episode and is written back to the engine
file, another account of the configured tier becomes the effective pair; the fallback never rewrites the operator's
`configured` pair. Three: from a lower tier the tiers above are tried only when `engine-runtime.json` `probe_after`
has passed, which is the earliest future reset time a failing higher-tier error stated (`resets <ISO instant>`) or
one hour (`TIER_PROBE_S` = 3600 s); a missing or unparsable `probe_after` makes them eligible at once; eligibility
is recomputed on every turn from the file and the clock, so a probe that falls due during a fault back-off is taken
on the retry. Four: a failure classified `rate_limit` or `other`, a crash (rc 17) or a timeout (rc 124) is a fault
(`EngineFault`): the walk stops at that step, nothing is persisted, no tier or account changes, no episode starts,
the turn keeps its failed-turn bookkeeping and the retry runs the same engine first; one top-level line per fault
episode, `engine fault: tier <k> <acc> (<model>): <what>`, is durable in `logs/fault.json` before it is queued and
reconciled at start, and the episode ends silently at the next served turn; a console or self event gets the same
text in its reply file or `logs/self-replies.jsonl`. Five: a change of the effective pair inside an episode queues
`fallback moved (episode <id>): ... unavailable (<reason>); now running tier <k> ...` with the id
`fallback-<episode_id>-move-<n>`; the move is durable in the runtime file (`pending_notice`, `move_from`) until the
line is confirmed queued and the start-up reconcile finishes a pending one; while an episode is active the first
status line reads `engine: configured <operator pair> | effective <engine-file pair> | last turn ran on <runner>`.

The aliases. `models.json` drops `sonnet5` and `haiku4.5` and adds `gpt6.1`/`sol6.1` -> `gpt-6.1-sol` as coder-use
aliases, which the manager ladder refuses. The README and the `hydra` usage text describe the ladder, the floor, the
refusal, the status line and the unavailable line.

Tests: the eleven exempted baseline tests are replaced by same-name tests of the new contract; the two further
exemptions of the 2026-10-15 amendment (`test_engines.py::test_non_quota_failure_tries_next_without_persisting`, a
crash now faults; `test_b13_status.py::test_preserve_populated_runtime`, the comparison now skips the `engine policy:`
line) are rewritten in place and mirrored in `tests/manager/test_b12_stickiness.py`, which covers the five rules
(stickiness, the move notice, the hourly probe and the stated reset time, session errors and crash/timeout faults,
fault-notice restart, the configured/effective status line). The literal-only
migration in `test_switch_to_codex_and_back_lists_the_other_familys_files` is applied. `tests/manager/test_ladder.py`
adds ladder, rotation, unavailable, stale-file, persistence, custom/invalid policy, notice and help/README tests.
All tests use fake executables and fake posters in temporary homes.

## Open questions

The coder's question (start at the configured primary versus stay on the account that served) is settled by founder
rule 1 of 2026-10-15: the account that last worked serves first inside the configured tier, and the tiers above are
re-probed hourly (rule 3). Rule 4 makes every non-usage failure a fault that never moves the manager; a session-id
fault like the one of 2026-10-14 therefore repeats on the same engine until the back-off retries succeed or an
operator switches the pair by hand. The founder was told this and has not asked for a safety valve.
