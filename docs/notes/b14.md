# b14 notes: the session-in-use repair and the rule-4 safety valve

## What changed

Two invocation fixes in `manager/supervisor.py`. `_session_resumable(sid)` (used by the per-turn and the persistent
paths in place of the bare `_resume_allowed`) resumes a rolled-over id that never started successfully when the
CLI already created its transcript (`find_claude_transcript` under the engine's config dir), marking the intent
started at that moment; the check happens at the next invocation, after the runner killed the timed-out process
and after that turn's durable uncertain disposition (b8), both unchanged. In `_invoke_per_turn` a `--session-id`
start refused with `Session ID ... is already in use` (`SESSION_IN_USE_RE`) marks the id started and retries the
same message once with `--resume`; `record_attempt` gained `retried_resume` and writes the flag on that row. A
refused `--resume` is a fault as before.

Review of the build PR (#79): a refusal is recognised on stderr, or on stdout only when the output carries no
stream-json assistant/result record (a turn that ran and quoted the message is never replayed, b8 requirement 8); the
legacy engine-file upgrade passes `close_fault=False` so only an operator's selection closes a fault episode, and that
closer queues a pending fault or escalated line before closing; the hold on the faulted step no longer depends on a
recorded configured pair; a probe that fails for a usage reason is consumed (the next probe an hour out); one
`_claude_argv` builder serves every Claude start and retry; `_read_fault` delegates to the module reader; the hold
sets `persist_switch` directly and gives the fallback episode its reason only when it opens it. Declined: the
persistent path's rc-23 start-failure rows before the resumed start (b8's persistent start contract, unchanged; the
success row carries `retried_resume`).

The valve on founder rule 4. The fault episode in `logs/fault.json` now carries `count`, `last_at` and `step`
(tier, account, model); `_note_fault` counts consecutive faults on the same step and replaces the episode when a
different step faults. `_fault_valve`, called at every fault point of `run_engines`, opens the walk when the
episode on that step is at least `FAULT_ESCALATE_S` (1800 s) old and this fault makes `FAULT_ESCALATE_COUNT` (3):
the episode is marked `escalated` with `probe_after` one `TIER_PROBE_S` out, the one `engine fault escalated:` line
is queued (id `fault-<episode>-escalated`, durable before the enqueue, reconciled at start), and the walk goes on
as for a quota failure (later faults in that walk are recorded and skipped). At the start of a walk an escalated
episode keeps its faulted step out of the order until the probe is due, then puts it first; a step that serves
while the faulted one is on hold is persisted as a move. `_close_fault_episode(served)` keeps an escalated episode
open while the fallback step serves and closes it when the faulted step or the configured pair serves; an explicit
`set_engine` closes it too. `_fault_episode_line` renders the status line for an episode whose `last_at` is at
least 1800 s after `since`; `status_text` prints it after the `engine fallback:` line and `add_timer_event`
appends it to the daily digest event's text.

Tests: `tests/manager/test_b14_session.py` (18) replays both incidents from the sanitized rows of the spec
appendix, the thresholds, the escalation walk, the probe return with an explicit mode key, the faulting probe, the
floor, the explicit selection, the status/digest line and the real 2026-10-16 fault file. Every baseline test is
byte-identical; the frozen b12 acceptance keeps passing (a single fault still moves nothing).
