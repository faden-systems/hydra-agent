## What changed

The due rule (requirement 1). `Supervisor.compaction_due()` returns `(True, "tokens")` when the last measured
Claude context is strictly over `compaction.threshold_tokens` (default 300000), with the three guards unchanged
(the back-off after a failed rollover, an outstanding verification, the engine family); nothing else gates it.
`over_ratio` is retired: `COMPACTION_DEFAULTS` has no such key, `compaction_config()` does not return it, and a
configured value is ignored with one log line per supervisor start (`compaction.over_ratio is retired; the due
limit is threshold_tokens`, written by `Supervisor.__init__`). The 2026-10-14 production incident this fixes:
turns 1673-1675 measured 891,774 and 372,110 context tokens with the policy recording a `pending` line and never
compacting on its own.

The held path (requirement 2). Rollover is on by default; with an explicit `compaction.rollover_enabled: false`
the compaction makes no engine call, records `last.error` starting `held: automatic rollover is disabled`, keeps
`pending`, consumes `COMPACT`, and posts one buildlog line per held episode naming the measured context, the limit
(`threshold_tokens`) and the setting; a measured turn under the limit clears `pending` and ends the episode.
`hydra compact` reports `compacted at` (exit 0), `compaction failed at`, `compaction held:` and `compaction
unverified at` (exit 1) and never prints a success-looking line for a held or unverified outcome.

The CLI's own compactions (requirement 3). The transcript scan from the recorded offset is as the coders left it;
this build adds the once-per-episode diagnostic: a transcript path that exists but is not a readable file (a
directory at the session file's name) or a read error logs `cli compaction scan: transcript unreadable at <path>`
once, remembered in `logs/compaction.json` as `transcript_unreadable` until a scan of that path succeeds; the turn
always completes.

The status line (requirement 4). `context: <N> tokens (turn <n>) | due over <limit> | last compaction: <last>`
with `<limit>` the threshold itself; `due (<reason>)` only when requirement 1 would compact now, which includes the
engine-family guard (no `due` suffix while Codex is selected, even with a stale 3x Claude measurement).

The digest (requirement 5). As the coders left it, plus one case the baseline Codex fallback test exposed: a
track entry that is not a JSON object (legacy `{"tracks": {"t9": "review"}}`) has no fields to digest and is shown
as the record itself, its key included (`- t9: {"t9": "review"}`), so the state still reaches Codex. Message size
measured by the acceptance on its real-sized fixture (a 24-track, 141 KB state.json whose whole content the old
prefix carried): message bytes before: 141253 and message bytes after: 29983 (that turn's `message_bytes`, the
complete engine message with the digest, the memory preamble and the events). The real session: the production
`state.json` is 183,645 bytes and went whole into every turn message until this build; the last measured
production contexts in `logs/turns.jsonl` were 891,774 (turn 1673) and 372,110 (turn 1675) tokens before the
2026-10-14 17:04Z forced compaction.

Timer gating (requirement 10). `TIMER_TEXT` and the unconditional slot event are gone. The service loop calls
`Supervisor.timer_tick()` once per elapsed `timer.every_s` slot on the supervisor's clock (the interval re-read
every iteration; a slot that passes under `PAUSE` is consumed without a check; a changed interval renumbers the
slots without an extra check; the loop sleeps through the injected `sleep` when one was given). The tick is a
pure-Python change check against `logs/timer-snapshot.json`: GitHub through `<gh_bin> api` (the issues call first
with `since` = this repo's previous successful check, then the default branch head, the open PRs and per PR the
detail, the reviews and the check runs; every list one page of `per_page=100`), the coder log directories, the
work-status deadline, `logs/persistence.json`, the dogfood (when configured) and `engine-runtime.json`, each
guarded on its own (a failure keeps the previous entry, counts in `failures.<source>`, wakes once on the third
consecutive failure with `check failing: <source>`, resets on success). It queues one timer event only with a
reason (`timer: <reason>; ...`, the exact clauses of the spec), appends `{at, woke, reasons, cost_ms}` to
`logs/timer-checks.jsonl`, writes the snapshot only after a completed check, and returns the record. Two forced
wakes: the daily digest once per local date at `timer.digest_at` in `timer.digest_tz` (`digest: true` in the
payload; a snapshot initialised after that time records the date and never catches up) and max silence after
`timer.max_silence_s` without a timer wake, a new turn record or a change of the in-flight set, only while
something is in flight (a coder logs directory whose launcher pid is alive, an open PR whose `user.login` is the
manager's GitHub login as `gh api user` reports it, or a `waiting` work-status record on someone other than L with
a deadline), never when only L is pending. `hydra status` gains `timer: every <every_s>s | last check <at>
(<cost_ms> ms) | last wake <at>: <reasons or none>`.

Two choices the frozen acceptance pins and the spec text leaves open, recorded here rather than argued: a
work-status deadline counts as passed once it lies at or before the previous check's time (the acceptance's
operator-deadline case requires that a deadline written inside the current interval is not fired by the very
next check), so the wake comes at most two intervals after the deadline; and the persistence status `no_repo`
(every turn writes it when no faden clone is configured, as in every offline test) is treated as quiet like
`synced`, since it is a configuration state, not an event.

Interval (requirement 11). `timer_config(home)` merges `TIMER_DEFAULTS` with the `timer` section of config.json
on every call (`every_s` clamped to at least 30, `max_silence_s` to at least `every_s`, defaults when config.json
is unreadable); `add_timer_event` keeps the baseline id `timer-<slot>` for the default 900 s interval and uses
`timer-<every_s>-<slot>` otherwise, so a slot number reused after an interval change is a distinct event.
`manager/README.md` documents the `timer` section and the b11 compaction rules.

Tests (requirement 7). `tests/manager/test_b11_compaction.py` (a)-(e), (g), (i) by the untouched emergency tests,
(j), (n), (q); `test_b11_transcript.py` (f), (k); `test_b11_cli.py` (l); `test_b11_digest.py` (h), (m), (o), (p);
`test_b11_timer.py` (s), (t); `test_b11_persistent.py` (r); shared fakes in `tests/manager/b11_helpers.py`. The
two baseline tests that contradict the spec are replaced under the new contract:
`test_rollover.py::test_held_when_rollover_disabled_records_diagnostic_without_engine_call` (plus
`test_rollover_is_enabled_by_default`) and
`test_compaction.py::test_hydra_compact_cli_schedules_and_status_shows_forced` (plus
`test_hydra_compact_cli_held_without_loop_when_disabled`). The baseline Codex fallback test
(`test_engines.py::test_codex_fallback_gets_handoff_and_state_on_stdin`), which ff000b0 had regressed, passes again
through the non-object track-entry case above.
