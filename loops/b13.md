# b13: truthful engine status

Owner: manager; founder-authorized manager build, no coder. Small status-only loop.

## Problem
On 2026-10-14/15 both Claude accounts repeatedly failed with `Session ID ... already in use` (classification `other`); Codex succeeded. Persisted fallback episodes did not cover these errors, so status advertised the configured Claude engine without showing the actual runner.

## Requirements
1. Read logs/turns.jsonl and logs/attempts.jsonl, no model/network call and no new state files. Replace only the engine line with `engine: configured <acc> (<model>) | last turn ran on <acc> (<model>)`, appending ` | MISMATCH` when either account or model differs. Preserve a configured persistent-mode suffix if present. With no completed turn use `last turn ran on unknown (unknown)` and no MISMATCH.
2. Add `last turn attempts: <acc>/<model> <classification>: <reason, 80 chars>; ...; <acc>/<model> ok`. Preserve file order, all failures and successes. Normalize whitespace and cap each failure reason at 80 Unicode characters. Missing evidence reads `none recorded`; never infer success from a turn row.
3. Add `off configured engine: <N> turns since <YYYY-MM-DD HH:MM:SS PDT>, reason: <classification>` for the trailing consecutive completed ordinary turns whose account/model differs from current configuration. Stop on matching or unknown runner; omit for N=0. Count model differences too. Use most frequent configured-account failure classification across that streak's associated attempts; ties use first occurrence, absence `unknown`.
4. Add `accounts: ` with one semicolon-separated entry per ENGINE_ORDER in order, `<acc>: ok` if last recorded attempt succeeded, otherwise `<acc>: <classification> since <PDT time>` for consecutive failures since the account's most recent success (other accounts do not break streak). No recorded attempts: `<acc>: unknown`. Label uses latest failure; since uses first consecutive failure. Include `, reset <text>` from the latest failure when its reason contains `reset`/`resets` followed by a reset time. Explicit timezone offsets/UTC instants convert to PDT; local clock text without timezone is presented as PDT; unparseable timezone text is retained without inventing conversion.
5. Display-only classification: credits/credit-balance exhaustion and usage-limit errors => usage_limit; session-ID-in-use => session_in_use; otherwise retain recorded classification or `other`. Do not modify the runtime classifier. New timestamps use fixed UTC-07:00 labeled PDT, including winter fixtures, as explicitly requested. Existing status lines and formats (including existing timestamps) remain byte-for-byte unchanged except engine line; this resolves the all-times instruction as applying to new diagnostics without changing preserved lines.
6. Association: ordinary completed turns have numeric `at`, nonnegative numeric duration_s (runner may be unknown and remains a streak boundary); exclude kind=compaction. Attempts have second-resolution ISO timestamps and no turn IDs. Associate timestamps in [floor(turn.at), floor(turn.at+duration_s)] inclusive, with next ordinary turn in file order's floor(start) as exclusive upper bound when overlapping; current unfinished attempts outside the completed interval are excluded. Preserve JSONL order, skip malformed/non-object rows and invalid timestamps; do not crash on missing/empty logs. Unknown model stays unknown, never borrow configured model. Latest ordinary row by file order is last turn for new diagnostics.
7. Existing pytest tests/manager stays green, no removal or weakening. New tests cover real collision sequence across many turns, usage limit with second account success, credit/reset, same account different model, recovery, empty/malformed/partial logs, in-flight attempt exclusion, repeated failures and all existing non-engine lines unchanged. Use sanitized real record fields from Oct14/15 as fixtures (timestamps adjusted only for deterministic boundaries). Status must not mutate log/state data.
8. Notes docs/notes/b13.md: What changed, Evidence (measured test count and acceptance outcome), Open questions. Full frozen exit PASS before build PR merge. Reviewed spec PR (up to four rounds), reviewed build PR, then Hermes idle deployment; post actual VM hydra status in founder thread. b11 startup-marker recovery, engine order, fallback logic and b12 remain untouched.
