# Loop B4 - Threads that reach the manager, and a compaction policy for its Claude session

## Purpose
Two defects seen live. (1) Threads: a reply in a thread the manager is already part of did not wake it unless it was
mentioned again, and follow-ups sent "to the thread" were recorded by the bridge with `thread_ts: null`, so the
manager's replies landed as top-level posts. The design says: one thread per track, every message in it reaches every
agent on the track, replies stay in the thread. (2) Cost: the manager's Claude turns in the b3 test consumed 552k and
741k tokens each. The resumed session is long and nothing compacts it on a schedule. This loop fixes both.

## 1. Threads (`manager/bridge.py`)
- **Thread identity.** For every Slack event the bridge records `channel`, `ts`, and `thread_ts` = the event's
  `thread_ts` if present, else its own `ts` when the message is a thread root the manager will answer. Replies are
  posted with that `thread_ts`, never top-level, unless the originating message was itself top-level and had no
  thread (then the reply starts the thread on it).
- **Participation.** The bridge keeps `$HYDRA_HOME/threads.json` (`Bridge.note_own_post(channel, thread_ts)` records
  the manager's own posts; `Bridge.prune()` applies the 14-day rule): `{channel: {thread_ts: {joined_at, last_seen}}}`.
  A thread is joined when the manager is mentioned in it, when the manager posts in it, or when a message in it
  carries an `assignee:` line naming the manager. Once joined, every later message in that thread from an allowlisted
  sender is queued (instructs per the allowlist), mention or not. Messages in threads it has not joined, and
  top-level messages without a mention, are mirrored only.
- **Leaving.** `@manager leave` in a thread (founder only) removes it from `threads.json`; so does 14 days without a
  message (pruned on bridge start and daily).
- **Mirror.** Every mirrored line records `thread_ts` (null only for true top-level posts). The manager's own
  replies are mirrored with the `thread_ts` they were posted to.
- **Status.** `@manager status` adds `threads: <n> joined`.

## 2. Compaction policy (`manager/supervisor.py`)
- After every Claude turn the supervisor records the turn's input tokens (from `turns.jsonl`). When a turn exceeds
  `compaction.threshold_tokens` (default 300000), or when the session file exceeds `compaction.max_bytes`
  (default 50 MB), the supervisor schedules a compaction before the next turn.
- Compaction is a dedicated turn on the same Claude session with the message: "Compact: write everything from this
  session that must survive into MEMORY.md (facts, decisions, open questions, with dates), update
  MANAGER-HANDOFF.md, then reply only `compacted`." After it returns, the supervisor runs Claude Code's compaction
  (`/compact` through `claude -p --resume <id> "/compact"`), verifies the next turn's input tokens dropped below the
  threshold, and logs `{compaction: {before_tokens, after_tokens, at}}` in the ledger. If compaction fails, it posts
  one line in the buildlog and continues; it never discards the session.
- Codex is not compacted by the supervisor (its thread continuity is via `resume --last` and the handoff); every
  `compaction.codex_every_turns` Codex turns (default 25) the supervisor prepends a `[flush]` line asking it to write
  everything durable since its last flush to `MEMORY.md` and `codex/NOTES.md` before handling the events.
- Quiet hours: compaction prefers `compaction.quiet_hours` (default `[2, 5]`, meaning 02:00 to 05:00) evaluated in
  `compaction.quiet_hours_tz` (default `local`, the VM's timezone; any IANA name or `UTC` accepted) when the
  threshold is crossed by less than 25%; above that, it runs immediately before the next turn. The clock the
  supervisor is given is timezone-aware; it converts to `quiet_hours_tz` before comparing.
- `hydra compact` forces it; `@manager compact` (founder only) likewise. `status` shows `last compaction: <at>
  (<before> -> <after>)`.

## 3. Rule text (`manager/CLAUDE.md`)
"When a turn begins with `[compaction]`, do exactly that: move everything durable from this session into MEMORY.md
with dates, refresh the handoff, reply `compacted`, nothing else."

## 4. Tests (`tests/manager/`)
Thread identity on root and reply events; join on mention, on own post, on assignee line; queued without mention
after join; not queued before join; leave; prune; mirror `thread_ts`; reply posting target; status line. Compaction
trigger by tokens and by bytes; the compaction turn's message and the `/compact` call (recording fake `claude`);
ledger entry; failure path posts once and keeps the session; Codex periodic memory flush; quiet-hours deferral and
the 25% override; `hydra compact` and `@manager compact` authority.

## Exit criteria
`loops/b4.exit.sh`: fence (`manager/`, `tests/manager/`, `setup/manager-vm.md`); pytest; the exit-owned
`loops/b4.acceptance.py`: with a fake Slack client, a thread the manager joins by mention receives three later
replies without mentions and all three are queued with the right `thread_ts`, the manager's reply is posted into
that thread (not top-level), a reply in an unjoined thread is mirrored but not queued, `leave` stops delivery; a
compaction scheduled after a turn whose recorded tokens exceed the threshold runs a `[compaction]` turn then
`/compact` on the same session id (recording fake), the ledger has the compaction entry, and a failing `/compact`
leaves the session id unchanged with one buildlog post; then b1 to b3 acceptance still pass.
