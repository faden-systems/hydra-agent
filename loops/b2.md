# Loop B2 - Shared memory across engines, and `engine acc=... model=...`

## Purpose
The manager runs on three engines (`claude-r2d2`, `claude-l`, `codex`). The two Claude accounts share one config
directory, so a switch between them keeps the transcript and Claude Code's own memory notes. Codex has neither: it
starts from `MANAGER-HANDOFF.md` and `state.json`, and it correctly said "I don't know" when asked about something
that lived only in the Claude transcript. This loop makes memory shared and ordered across engines, so a switch in
either direction starts from the latest facts, and it extends the engine command with a model parameter.

## 1. Shared memory folder (in the faden clone, committed by the supervisor)
`factory/manager-memory/`:
- `MEMORY.md`: the canonical notes both engines read and write. Every entry starts with `YYYY-MM-DD HH:MMZ
  <engine>:`. Sections: `## Facts`, `## Decisions`, `## Conflicts`.
- `claude/`: a snapshot of Claude Code's memory files (`$CLAUDE_CONFIG_DIR/projects/<encoded cwd>/memory/*.md`)
  copied by the supervisor after every Claude turn. Codex reads it; nothing writes it but the snapshot.
- `codex/NOTES.md`: what the manager writes when it runs on Codex. Claude reads it; Codex writes it.
- `MANAGER-HANDOFF.md` moves here from `$HYDRA_HOME` (a symlink stays at the old path); the supervisor stamps a header
  `updated_at: <UTC ISO>` and `engine: <name>` on every rewrite.
- `LEDGER.jsonl`: one line per turn, appended by the supervisor: `{turn, at, engine, model, files_written:
  [paths relative to the folder], handoff_sha}`. This is the clock; engines never compare file dates themselves.

## 2. The preamble (supervisor, deterministic)
Before every turn the supervisor prepends to the batched message:
```
[memory] last turn: <at> on <engine> (turn N). your last turn on <this engine>: turn M at <at> | none.
[memory] changed by other engines since then: <path> (<at>) ...  | none (same engine since your last turn).
[memory] MEMORY.md last written <at> by <engine>. Read the changed files before acting.
```
"Other engine" means the other family: `claude-r2d2` and `claude-l` are one engine for memory purposes (same
transcript, same Claude memory), `codex` is the other. "Changed by other engines" is computed from the ledger: files
in `files_written` of turns after M (this family's last turn) whose family differs, plus the handoff if its `engine`
header is from the other family. Paths are relative to `factory/manager-memory/`. The three lines are exactly:
```
[memory] last turn: <at> on <engine> (turn N). your last turn on <family>: turn M at <at> | none.
[memory] changed by other engines since then: <path> (<at>), ... | none (same engine since your last turn).
[memory] MEMORY.md last written <at> by <engine> | never. Read the changed files before acting.
```
The supervisor exports `HYDRA_HOME` and `HYDRA_MEMORY_DIR` (the absolute path of `factory/manager-memory/`) to every
engine process, so the rule's "write to MEMORY.md" has an unambiguous target; `files_written` in the ledger is
computed by comparing the folder's file hashes before and after the turn, so an engine's own writes to `MEMORY.md`
and `codex/NOTES.md` are recorded without the engine reporting them.

## 3. The engines' rule (append to `manager/CLAUDE.md`, mirrored by `AGENTS.md`)
"If the memory preamble lists files changed by another engine, read them before anything else. Newer wins: where a
newer note contradicts what you remember, the newer note is the truth; update `MEMORY.md` so it says so, with both
dates. If you cannot tell which is right and it matters, put both under `## Conflicts` in `MEMORY.md` and ask the
founder in the thread. Write anything durable you learned this turn to `MEMORY.md`; on Codex also to
`codex/NOTES.md`. The transcript is not memory."

## 4. Bookkeeping after every turn (supervisor)
Snapshot Claude's memory folder (Claude turns), stamp the handoff header, append the ledger line, mirror the
manager's own reply into the channel log (today the bridge mirrors everyone but the manager), commit the memory
folder with `state.json` and the logs, push.

## 5. `engine acc=<account> model=<alias>`
- Syntax, Slack (`@manager engine ...`, founder only) and CLI (`hydra engine ...`): `engine acc=<claude-r2d2|
  claude-l|codex> [model=<alias>]`. The old form `engine <account>` keeps working and means "acc=<account>, family
  default model". `engine` alone prints the current pair.
- Aliases (`manager/models.json`, extendable): Claude: `fable5.1 → claude-fable-5-1` (default), `sonnet5 →
  claude-sonnet-5`, `opus5 → claude-opus-5`, `haiku4.5 → claude-haiku-4-5-20251001`; Codex: `gpt6`/`astra →
  gpt-6-astra` (default), `gpt5.6`/`sol → gpt-5.6-sol`. Full model ids are accepted as-is. A model from the wrong
  family for the account, or an unknown alias, is rejected with the list of valid ones and nothing changes.
- Persistence: `$HYDRA_HOME/engine` becomes JSON `{"acc": ..., "model": ...}` (the supervisor reads the legacy
  one-word file and upgrades it). The Claude engine gets `--model <id>`; Codex gets `-m <id>`.
- Automatic switching on quota keeps the model alias when it exists in the new family, else the family default, and
  says so in the thread note: `engine: claude-l (claude-fable-5-1)`.
- `status` shows `engine: <acc> (<model>)`; the ledger and `turns.jsonl` record both.

## 6. `hydra update`
Pulls `main` in the hydra-agent clone (`HYDRA_REPO`, default `/srv/hydra/repos/hydra-agent`), re-copies `manager/`
into the deploy dir (`HYDRA_APP`, default `/srv/hydra/manager/app/manager`), refreshes the `AGENTS.md` link,
restarts both services with `systemctl restart hydra-bridge hydra-manager` (`systemctl` resolved from `PATH`, so a
test can substitute a recorder), and prints `updated to <commit>` with the clone's new HEAD. The manager reported its deployed `CLAUDE.md` as stale versus main; this is
the fix, and the runbook says to run it after every merge to `manager/`.

## Tests (`tests/manager/`)
Preamble from a synthetic ledger (other-engine files listed, same-engine case says none, handoff engine mismatch
listed); snapshot copy; header stamping; ledger line per turn with model; own-reply mirroring; engine file parse,
upgrade, aliases, family check, rejection; CLI and bridge forms of the command; auto-switch model carry-over;
`hydra update` on a temp clone.

## Exit criteria
`loops/b2.exit.sh`: fence (`manager/`, `tests/manager/`, `setup/manager-vm.sh`, `setup/manager-vm.md`); pytest; the
exit-owned `loops/b2.acceptance.py`: two recording fake engines alternate turns; asserts the ledger, the snapshot, the
handoff header, the exact three preamble lines on a switch turn and on a same-family turn, the ledger cutoff (a
file written by this family before its last turn is not listed), `MEMORY.md` and `codex/NOTES.md` written by the
engines landing in the folder and in `files_written`, the manager's reply in the channel mirror, the memory folder
committed to a temp remote, the model id on the engine argv from the JSON engine file, alias and family rejection,
legacy file upgrade, `hydra engine acc=claude-l model=sonnet5` round trip, and `hydra update` against a temp clone
with a newer remote and a recording `systemctl`; then `loops/b1.acceptance.py` (updated for the JSON engine file)
still passes.

## After merge (Hermes)
`hydra update`; `@manager engine acc=claude-r2d2 model=fable5.1`; `@manager status`; force `acc=codex`, ask a question
whose answer is only in `claude/` snapshot, confirm Codex reads it; back to `claude-r2d2`.
