# Loop B5 - Working indicator: an 👀 reaction while the manager is on a turn

## Purpose
A manager turn can run several minutes (a compaction ran 133 s) with no sign of life in Slack. The founder chose the
quietest signal: react to the triggering message while the turn runs, remove the reaction when the reply is posted.
No progress text, no streaming.

## Behaviour
- When the supervisor starts a turn, for every Slack event in the batch it calls `reactor.add(channel, ts, "eyes")`.
- When the reply for that event has been delivered, `reactor.remove(channel, ts, "eyes")`. On delivery failure
  (reply pending) the reaction stays until the pending reply is delivered. On a turn error (all engines failed) the
  reaction is replaced by "x" and removed when a later turn handles the event.
- Timer and CLI events have no Slack message; nothing is reacted to.
- Reactions are best-effort: a failed `reactions.add` (missing scope, rate limit, deleted message) is logged once per
  hour and never blocks the turn.
- The manifest in `docs/`/`setup/` gains the `reactions:write` bot scope; `bridge.py --check` warns (not fails) when
  the token lacks it (`auth.test` cannot show scopes, so the check does a dry `reactions.add` on the bot's own last
  message if any, else warns that the scope is unverified).

## Interfaces
`Supervisor(..., reactor=)` where `reactor` has `add(channel, ts, name)` and `remove(channel, ts, name)`; the bridge
provides the real one over `slack_sdk`; tests pass a recorder. `turns.jsonl` lines gain `reacted: [ts...]`.

## Tests (`tests/manager/`)
Reaction added for each Slack event at turn start and removed after delivery; kept while a reply is pending and
removed once delivered; replaced by "x" on an all-engines failure and cleared when a later turn handles the event;
no calls for timer/cli events; add() raising does not block the turn and is logged once per hour.

## Exit criteria
`loops/b5.exit.sh`: fence (`manager/`, `tests/manager/`, `setup/manager-vm.md`, `setup/slack-manifest.json`); pytest;
the exit-owned `loops/b5.acceptance.py`: a recorder reactor sees `add eyes` before the fake engine runs and `remove
eyes` after the poster is called, for two events in one batch; a flaky poster leaves the reaction until the pending
reply is delivered; a quota-only engine set yields `x`; `add` raising keeps the turn working; timer event: no calls;
then b1 to b4 acceptance still pass.
