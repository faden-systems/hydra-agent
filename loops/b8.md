## Required behavior

1. At most one long-lived Claude process per account, and only one writer to the manager
conversation across accounts, supervisor, and attach. Each turn sends a new stream-json
user message and waits for its terminal result. No overlapping request or cross-turn output.
Parse each request's usage and actual error text, including is_error results while the
process remains alive. Preserve existing request deduplication and first-request context
measurement; do not add aggregate result usage a second time.
2. Account, model, vendor, or mode changes apply at a turn boundary. Stop the old process
before starting the selected engine; preserve the conversation ID on Claude restarts and
account/model switches. Use the selected login environment without leaking it into logs.
Existing vendor-specific conversation identities and memory transition behavior remain intact.
3. A process crash fails the interrupted turn truthfully; restart on the next turn. At the
configured turn timeout interrupt, then kill after a bounded grace and reap the process tree;
restart for the next turn. Never silently replay a partly executed turn after crash or hang.
4. One planned daily restart at a configured quiet hour, deferred until no turn or attach
owns the session. Persist the completed daily restart date to avoid repeated restarts after
supervisor recovery. Report planned and unexpected restarts separately.
5. hydra attach requests a park after the current turn, takes exclusive writer ownership,
and resumes supervisor service on exit, including abnormal attach exit. No background Claude
writer may share its conversation with the interactive process. A parked process may be
stopped and later resumed using the same ID if native parking cannot guarantee exclusivity.
6. Automatic rollover is emergency-only: an actual resume failed specifically because the
conversation is too long AND the account has been shown working. Auth, quota, rate, network,
and ambiguous failures cannot qualify. Ordinary token thresholds must not rotate sessions.
Preserve old conversation data and durable memory/transition recovery. Do not emulate
native compaction by starting a new conversation on routine turns.
7. engine mode accepts persistent or per-turn through hydra engine mode=... and the existing
founder-authorized @manager engine command. Default is per-turn, including missing settings.
Invalid values are rejected atomically. Mode selection persists across supervisor restart.
Codex invocation always stays per-turn regardless of the configured Claude mode.
8. Two consecutive failed starts fall back to per-turn for that turn with one alert. Startup
failure is distinguished from a submitted request failure, and fallback must never duplicate
a submitted request. Successful start clears the consecutive counter. Expose configured and
effective modes and fallback reason; a transient fallback does not erase the selected mode.
9. status shows mode, live process uptime, turns served, account/model and whether parked.
Stale PID data after restart must never appear as a healthy running process. Keep existing
configured/effective engine, failure and waiting information.

## Identity contract interface

`supervisor.credential_identity(home, name, spec, observed=None)` resolves a credential label
without logging its secret. Return `verified`, `automatic_allowed`, `account_id`,
`verified_at`, and `mismatch`. `observed`, when supplied by the real CLI adapter, contains
`account_id` and `token_bound`; only an authoritative token-bound observation can reject a
mismatched observed account. A cached-login observation cannot override manual verification.
The adapter must establish token binding from actual CLI evidence, not assert it unconditionally.

Manual sidecar `<credential.env>.identity.json` schema1 contains label, account_id,
token_sha256 (digest of the parsed token, not file whitespace), verified_at UTC timestamp,
method and evidence link. Missing, malformed, wrong-label or token-stale metadata is unverified.
An authoritative observed mismatch always blocks session start even with current manual metadata.
Status and fallback notes consume this resolver; run_engines checks automatic_allowed before
invoking a fallback credential. Tests use generated dummy values only. Real CLI identity support
remains a discovery gate; this interface does not claim that support has been established.

### Queued crash and timeout acceptance (PR45 B1)

Process-tree reaping (PR45 2.5): every fixture hang now spawns a TERM-resistant descendant (it
ignores SIGTERM, SIGINT and SIGHUP) in the CLI's process group and records its pid. After the
timeout interrupt, kill and reap, the frozen gate requires, before the next request starts, that
the hung process has no `/proc` entry at all (an unreaped zombie fails) and that the descendant is
gone within half a second; the recovered turn must run in a fresh process. Both the lifecycle hang
and the queued-event hang are checked, and the lifecycle gate re-checks that no recorded descendant
is alive at its end, so fixture cleanup can never conceal a leak. Implementations must kill the
whole process group (or walk the tree) with SIGKILL after the bounded grace, not only the child pid.


The frozen lifecycle gate sends CRASH and HANG events through append_event/run_once
with two available verified fixture accounts. The child records a side effect after
receiving the request and before failing. There must be exactly one execution across
inline routing, ticks after retry backoff, supervisor reconstruction, and delivery of a
fresh event. The fresh event must complete. An uncertain submitted request must receive
a durable disposition that prevents automatic replay; it must not be reported successful.
These checks do not replace the lower-level process lifecycle checks. The offline
baseline currently reproduces duplicate execution through the second account.
