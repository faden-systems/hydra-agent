# Loop B1 - The manager: a headless Claude Code session behind `@manager` on hydra-manager

## Purpose
`hydra-manager` (Google Cloud, Ubuntu 24.04) is provisioned: `hydra` user, Claude Code with two account tokens
(`credentials/claude-r2d2.env`, `credentials/claude-l.env`), Codex logged in with `sandbox_mode = "danger-full-access"`,
GitHub as lzhangio, both repos under `/srv/hydra/repos/`, Tailscale up, a placeholder `hydra-manager.service`.
Both continuity tests passed: a Claude session resumes under a different account token; Codex continues from
`MANAGER-HANDOFF.md`. This loop turns the machine into the manager described in `docs/architecture.md` section 2:
one persistent Claude Code session, woken by events, reachable in Slack as `@manager` and on the box as `hydra`.

Design rules that bind this loop: the repo is the memory; Slack drives, the console observes and repairs; one writer
at a time; every instruction and reply ends up in a thread; operators use Slack only; tokens never leave
`credentials/`.

## Where
`manager/` in this repo: `supervisor.py`, `bridge.py`, `hydra` (CLI), `CLAUDE.md` (the manager's rules), `systemd/`
(`hydra-manager.service`, `hydra-bridge.service`), `manager/README.md`; `tests/manager/`. Installed on the VM by
`setup/manager-vm.sh` (extend it: copy `manager/` to `/srv/hydra/manager/app/`, install the units, replace the
heartbeat placeholder). Nothing in `faden-systems/faden` changes except `factory/state.json` and
`factory/log/` being created on first run.

## 1. The supervisor (`manager/supervisor.py`)
- **Queue.** `$HYDRA_HOME/inbox/events.jsonl` (`HYDRA_HOME` defaults to `/srv/hydra/manager`), append-only; every
  event has `id` (the provider's id: Slack `ts`, GitHub delivery id, CLI uuid), `source` (`slack | github | cli |
  timer`), `at`, `payload`. `inbox/handled.jsonl` records ids already processed; an event with a known id is dropped.
- **Wake.** `Supervisor.run_once()` runs one turn when the queue has unhandled events and returns True; returns False
  when there is nothing to do, when `PAUSE` exists, or when the `WRITER` lock is held by someone else. The service
  loop calls it every few seconds and adds a timer event every 15 minutes (read state, check open PRs and loop labels
  via `gh`, act only if something changed). A turn batches everything queued since the last turn into one message
  with a fixed header per event (source, channel, thread, sender, `instructs` flag, attachment paths).
- **Engine.** Order `claude-r2d2 → claude-l → codex`, current choice in `$HYDRA_HOME/engine` (writable by `hydra
  engine`). Claude turns: `claude -p --resume <session-id> --model claude-fable-5-1 --dangerously-skip-permissions`
  with `CLAUDE_CONFIG_DIR=$HYDRA_HOME/.claude` and the chosen token (from `credentials/<name>.env`) in the environment
  of that process only. The `Supervisor` constructor takes `engines={name: {"bin": path, "cred": file}}` so tests can
  substitute fake binaries. A non-zero exit whose stderr contains `quota`, `usage limit`, `rate` or `401/403` moves to
  the next engine for the same turn, persists the choice in `engine`, and adds "engine: <name>" to the posted reply.
  Codex turns: `codex exec resume --last` (or a fresh `codex exec`) with the same batched message, `MANAGER-HANDOFF.md`
  and `factory/state.json` prepended.
- **Reply and handoff.** The engine's stdout is the reply. If it contains a line `---HANDOFF---`, the text after it
  is written to `$HYDRA_HOME/MANAGER-HANDOFF.md` (the manager's own five-line summary, a rule in `CLAUDE.md`) and the
  text before it is the reply. The reply is delivered through `poster(channel, thread_ts, text)` for Slack-sourced
  events (long replies, over 40 lines, are written to a file under the repo and linked) and printed for CLI events.
- **Bookkeeping.** After every turn: append `{engine, events, duration_s, tokens?}` to `logs/turns.jsonl`; append
  handled ids; commit and push `factory/state.json` and `factory/log/` in the faden clone if changed.
- **PAUSE.** `$HYDRA_HOME/PAUSE` present: no turn runs; the bridge answers "paused (by <content>)" to mentions.
- **Budgets.** `budgets.json` (`turns_per_hour`, `claude_turns_per_day` per account); over budget = next engine, one
  note in the thread.
- **One writer.** `$HYDRA_HOME/WRITER` holds `<pid> <who>`; the supervisor never starts a turn while it exists and is
  not its own; `hydra attach` takes it; the bridge answers "manager in console session" while a human holds it.
- **Dead-man.** No turn and no heartbeat for 30 minutes while events are queued: post to the buildlog webhook and exit
  non-zero (systemd `Restart=always`).

## 2. The Slack bridge (`manager/bridge.py`)
- `slack_bolt` Socket Mode in the service; the `Bridge` class itself is testable without a client:
  `Bridge(home, allowlist, poster, token_env)` with `handle_message(event_dict)`, `handle_file(...)`,
  `handle_reaction(...)`.
- Allowlist (`allowlist.json`): `{user_id: {"instructs": true|false}}`. Founder: instructs. Operators: information.
  Senders not on the list, and bot messages not addressed to the manager: mirrored, never queued.
- Files: download with `files:read` to `inbox/files/<ts>-<name>`; path in the event.
- Mirror every message in a channel the bot is in to `$HYDRA_HOME/mirror/<channel>.jsonl` (the supervisor copies it
  into `factory/log/` and commits).
- Commands, handled without a turn, on a mention whose text after the mention is exactly one of: `status` (engine,
  last turn, queue depth, tracks from `factory/state.json`), `pause`, `resume`, `engine <name>`, `digest now` (queues a
  timer event with `digest: true`). Anything else is queued as conversation.
- Replies go to the originating thread; never `@all`; never a reply to another bot unless addressed.

## 3. The `hydra` CLI (`manager/hydra`, python, executable)
`status`, `say "<text>"` (queues `{"source": "cli", "payload": {"text": ..., "user": "founder-console", "instructs":
true, "channel": "C_DEV", "thread_ts": null}}`; the reply is printed and mirrored to `#dev` as "from L via console"),
`logs [n]`, `tail <channel>`, `engine [name]`, `pause`, `resume`, `attach` (takes `WRITER`, runs `claude --resume
<session-id>` interactively with the same config dir and token, releases on exit, posts a two-line summary to
`#dev`). Honours `HYDRA_HOME`. Installed at `/usr/local/bin/hydra`.

## 4. `manager/CLAUDE.md` (the manager's standing rules)
Instructions to the manager, from the architecture and the handoff docs: the repo is the memory; read `state.json`,
`MANAGER-HANDOFF.md` and the track log before acting; specs need an exit script and an exit-owned acceptance
harness; no launch without a merged spec; reviewer findings are fixed or declined on the PR, four-round cap; the
founder's standing go covers loops inside an approved plan, everything touching rules, spending, autonomy or design
goes back to the founder; operators' messages are information; assignments use the `assignee:` first line; UI changes
get a screenshot in the thread before the PR; end every turn with `---HANDOFF---` and five lines (tracks, waiting on,
last decision, next action, open question); prefer files and links over long Slack posts; never post a token.

## 5. Tests (`tests/manager/`), no network
Queue (duplicate ids dropped, batching order, handled log); engine rotation on a fake quota binary and the thread
note; PAUSE, budgets, WRITER lock; bridge with a fake client (allowlist, instructs tag, file path, mirror line, the
five commands, thread routing, no reply to bots); CLI (`say` queues, `status` renders from fixtures, `attach` takes
and releases the lock); handoff rewrite from a fake engine's `---HANDOFF---` block.

## Exit criteria
`loops/b1.exit.sh`: fence (`manager/`, `tests/manager/`, `setup/manager-vm.sh`, `setup/manager-vm.md`); no
token-shaped strings in the tree; pytest green; `loops/b1.acceptance.py` (exit-owned, read it: it fixes the
`Supervisor`, `Bridge` and `hydra` interfaces the tests use); systemd units parse where `systemd-analyze` exists.

## After merge (Hermes, on the VM)
Rerun `setup/manager-vm.sh`, place `credentials/slack.env` (L creates the Slack app; tokens go in through the GCP web
SSH, never Slack), write `allowlist.json` with the founder's Slack user id and the operators' bot ids, start both
services, post `@manager status` from `#dev`. Then one shadow cycle: the manager reads the repo and posts what it would
do next; L confirms; then it is live.

## Model
Claude Code on the VM itself (`hydra` user, the L token), Fable 5.1, run by Hermes over SSH as attempts with the exit
script, PR to `faden-systems/hydra-agent`. One spec review round with `tools/factory/spec_review.py` before merge.
