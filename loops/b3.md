# Loop B3 - The transition read: the incoming engine reads the other engine's transcript at a family switch

## Purpose
b2 made memory shared through files. What is said in a Claude session and not written down still does not reach
Codex, and vice versa. Summaries lose the manager-level detail, and a family switch is rare (an account running out
of usage), so the design is: at every switch, the incoming engine reads the other family's transcript since the last
switch, flattened to plain text with nothing dropped, cut to a token budget, inline in its first turn.

## 1. Sources (both plain-text JSONL, UTF-8)
- Claude Code: `$CLAUDE_CONFIG_DIR/projects/<encoded cwd>/<session-id>.jsonl`. Lines with `type` in `user`,
  `assistant`, `summary`; `message.role`, `message.content` as a string or a list of blocks (`text`, `tool_use` with
  `name` and `input`, `tool_result` with `content`), `timestamp`.
- Codex: `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-*.jsonl` (the latest whose `session_meta` matches the manager's
  cwd, or the file `codex exec` reported). Lines with `timestamp`, `type`, `payload`; messages are `payload.type ==
  "message"` with `role` and `content` (string or list with `text`/`input_text`/`output_text`); tool calls come in
  two shapes and both must be handled: `function_call` (`name`, `arguments`) with `function_call_output`
  (`output`), and `custom_tool_call` (`name`, `input`) with `custom_tool_call_output` (`output`); the recorded real
  rollout uses the custom shape exclusively. Reasoning summaries are dropped.
- Recorded real files from the VM (one of each, secrets scrubbed) are committed under `tests/manager/fixtures/transcripts/`
  and the flatteners are tested against them, not only against synthetic lines.

## 2. `manager/transcript.py`
- `flatten_claude(path, since_ts=None) -> list[Entry]` and `flatten_codex(path, since_ts=None) -> list[Entry]`,
  `Entry = {at, role, kind ("text"|"tool_call"|"tool_result"), text}`. Rules: every user/assistant text kept whole;
  tool calls rendered as `tool <name>(<arguments>)`; tool results kept whole up to `tool_result_max_chars`
  (default 4000), then cut with `[... N more chars omitted]`; compaction `summary` lines kept as `summary:` entries;
  reasoning/thinking blocks dropped. Nothing else is summarized or reordered.
- `render(entries) -> str`: `HH:MMZ role: text` per entry, blank line between turns.
- `window(text, max_tokens) -> (text, meta)`: keeps the newest part up to `max_tokens` (estimate: chars / 3.5),
  cutting at an entry boundary; `meta` = `{entries_total, entries_kept, first_at, last_at, est_tokens, cut}`; the
  window starts with one line: `Transcript window: <first_at> to <last_at>, <entries_kept> of <entries_total>
  entries; <n> earlier entries not included.`

## 3. The supervisor at a family switch
- A family switch is detected when the engine family of the turn about to run differs from the family of the last
  ledger turn. The supervisor then builds the transition read from the other family's transcript, `since` the `at`
  of the last ledger turn whose family equals the incoming one (the moment this family last ran), or from the start
  of that transcript if this family has never run. Comparison is on the transcripts' own timestamps against the
  ledger's, both UTC ISO; the supervisor takes an optional `clock` callable so tests control time.
- The read is placed inline after the three `[memory]` lines, under the header:
  `[transition] engine family switched from <a> to <b> at <at>. Below is the other engine's transcript since the last
  switch, flattened, nothing summarized. Read it fully before acting. Then write to MEMORY.md anything in it that must
  survive the next switch.`
- Ledger line gains `transition: {from, to, source_path, first_at, last_at, entries_kept, entries_total, est_tokens}`.
- Config (`$HYDRA_HOME/config.json`, defaults): `transition.max_tokens` 100000, `transition.tool_result_max_chars`
  4000, `transition.enabled` true. The same window is also written to
  `factory/manager-memory/transition/<from>-to-<to>-<at>.md` for the record.
- Same-family switches (claude-r2d2 ↔ claude-l) do not trigger it: same transcript.
- If the other family's transcript cannot be found, the preamble says so in one line and the turn proceeds.

## 4. Rule text (append to `manager/CLAUDE.md`)
"After a `[transition]` block: read it entirely before acting. Anything in it that must survive the next switch goes
into `MEMORY.md` this turn, dated and tagged with the engine that originally said it."

## 5. Tests (`tests/manager/`)
Flatteners on the recorded fixtures (counts of entries by kind match the file: for the Codex fixture the number of
`tool_call` entries equals the number of `function_call` + `custom_tool_call` items and likewise for outputs, so a
schema variant cannot silently disappear; a known founder line and a known manager reply appear verbatim; a long tool result is cut at the cap with the marker; reasoning dropped); `window`
(cut at entry boundary, meta correct, newest kept); switch detection from the ledger (family, not account);
`since` from the last switch; the preamble header and the ledger field; config defaults; disabled flag; missing
transcript path.

## Exit criteria
`loops/b3.exit.sh`: fence (`manager/`, `tests/manager/`, `setup/manager-vm.sh`, `setup/manager-vm.md`); fixtures
present and scrubbed (no token-shaped strings); pytest; the exit-owned `loops/b3.acceptance.py`: a fake Claude
transcript containing a fact that appears nowhere in the memory folder; a switch to a fake Codex engine; the fake
records its stdin; the stdin contains the `[transition]` header, the fact verbatim, the window line, and the
`[memory]` lines before it; the ledger has the `transition` field; the same in reverse with a Codex rollout fixture
holding a Codex-only fact and a switch to Claude; a same-family switch produces no `[transition]`; `max_tokens`
respected (a large fixture is cut and the fact in the newest part survives, the oldest is dropped, meta says so);
then b1 and b2 acceptance still pass.
